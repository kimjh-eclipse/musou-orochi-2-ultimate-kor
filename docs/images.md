# 메뉴 이미지 처리

메뉴 제목·선택 버튼·무기 속성처럼 화면의 글자 자체가 이미지인 항목은 문자열 테이블을 번역해도 바뀌지 않습니다. 작은 표시와 선택 시 큰 표시가 별도 텍스처일 수도 있으므로 두 상태를 함께 추적합니다.

## 리소스를 찾는 방법

1. 화면 경로와 위치를 기록하고 문자열 출력인지 이미지 출력인지 구분합니다.
2. 후보 G1T를 추출해 텍스처별 contact sheet를 만듭니다.
3. 원문 모양과 주변 배경·테두리로 실제 사용 영역을 찾습니다.
4. 작은 제목, 큰 선택 항목, 비활성 상태, 하위 메뉴 제목을 각각 대응시킵니다.
5. entry·texture·사각형 좌표·원문·번역문을 명시적으로 기록합니다.

예를 들어 무기점의 상단 소제목과 던전 층수는 캠프 전용 리소스로 추정했지만, 실제로는 공통 entry 40의 texture 52에 있었습니다. 화면 이름만으로 리소스 위치를 추정하면 이런 누락이 반복됩니다.

## G1T 헤더와 PS3 해석

확인한 G1T는 `G1TG` 서명과 버전 바이트를 가지며, `+0x08`부터 파일 크기·테이블 위치·텍스처 수·플랫폼 값이 u32 BE로 이어집니다. 텍스처 시작은 테이블 위치에 상대 오프셋을 더해 계산합니다. 텍스처 헤더에는 포맷과 압축된 치수 비트가 들어 있습니다.

일반 파서의 치수 비트 순서를 PS3에 그대로 쓰면 폭과 높이가 뒤바뀔 수 있습니다. 해당 PS3 리소스의 올바른 차원과 블록 pitch를 확인한 뒤 디코딩해야 합니다. 폰트의 잘못된 두 면 해석도 이 문제에서 발생했습니다.

| 포맷 값 | 처리 |
|---|---|
| 1 | 비압축 4채널; 확인한 공통 entry 40은 바이트 순서 **ARGB** |
| 6 | BC1 / DXT1 |
| 7 | BC2 / DXT3 |
| 8 | BC3 / DXT5 |

과거 범용 렌더러의 BGRA 가정은 공통 entry 40에 맞지 않았습니다. 단순히 “RGBA 4바이트니까 맞다”고 볼 수 없으며, 원본 색·알파를 확인해야 합니다. 이 entry의 ARGB 순서를 다른 모든 리소스에 무조건 일반화하지도 않습니다.

## BC2·BC3 수정 단위

둘 다 4×4픽셀 블록당 16바이트이며 알파 표현이 다릅니다.

- BC2: 16픽셀의 4비트 알파를 8바이트에 저장하고 색 블록 8바이트를 덧붙입니다. 개발 인코더는 알파를 17단계 간격으로 양자화합니다.
- BC3: 두 알파 끝값과 3비트 선택 인덱스를 앞 8바이트에 저장하고 색 블록 8바이트를 덧붙입니다.

수정 사각형은 블록 경계에 맞춥니다. 인접 텍스트가 같은 블록에 있으면 글자 사각형만 생각해 잘라 쓰는 것으로 충분하지 않습니다. 블록 전체에 영향을 주기 때문입니다.

```python
assert all(value % 4 == 0 for value in (x0, y0, x1, y1))
assert 0 <= x0 < x1 <= texture_width
assert 0 <= y0 < y1 <= texture_height
```

개발 테스트에서 사용한 알파 오차 허용치는 BC2 최대 8, BC3 최대 18이었습니다. 이는 해당 인코더·테스트의 기준이며 모든 BC3 인코더의 수학적 최대 오차를 뜻하지 않습니다.

## 번역 이미지 제작과 보존

글자를 지울 때 배경·테두리·아이콘을 함께 지우지 않도록 교체 영역을 제한합니다. 새 글자는 실제 사용 크기에 맞춰 여백과 획을 조절하며, 긴 번역은 무조건 확대된 사각형에 덮어쓰지 않습니다. 작은 텍스트가 옆 라벨에 겹칠 수 있기 때문입니다.

최종 검사는 다음 두 층으로 나눕니다.

1. **바이너리 보존:** G1T 헤더·텍스처 메타데이터·전체 길이 유지, 허용 블록 밖 바이트 동일, 압축 후 슬롯 용량 준수.
2. **디코딩·표시:** 결과를 재디코딩해 허용 영역 밖 픽셀 동일, 글자 획·알파 확인, 실제 화면에서 선택·비선택 상태와 확대 잘림 확인.

재디코딩 결과가 좋다는 사실만으로 게임에서 잘리지 않는다고 결론내릴 수는 없습니다. 게임이 텍스처를 사용하는 UV 영역·스케일·클리핑도 영향을 줍니다.

## 최근 반영과 남은 영역

최근 공통 메뉴 보완은 entry 40의 texture 49·52·53·54·55에 있는 128개 라벨을 대상으로 했습니다. texture 55는 BC2이므로 다른 BC3 텍스처와 같은 방식으로 처리하면 안 됩니다. 무기 속성 58개가 있는 texture 58과 장비 제목 계열 texture 60의 기존 변경도 보존했습니다.

편집 화면의 톱니바퀴·배경과 겹치는 texture 57 계열은 별도 보존 작업이 남아 있습니다. 아직 조사하지 않은 이미지도 있을 수 있습니다. [알려진 문제](known-issues.md)에 실제 검증 상태를 기록합니다.

게임 목록 로고인 `ICON0.PNG`는 G1T가 아니며 별도의 [메타데이터 처리](metadata.md)를 사용합니다.
