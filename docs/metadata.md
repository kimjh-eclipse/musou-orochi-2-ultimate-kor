# 실행 파일·제목·아이콘

같은 “타이틀”이라도 실행 파일의 UI 문구, 게임 목록 이름, 목록 아이콘, 인게임 타이틀 텍스처는 서로 다른 데이터입니다.

| 위치 | 바꾸는 대상 | 바꾸지 않는 것 |
|---|---|---|
| `USRDIR/EBOOT.BIN` | 실행 파일 내 UI 문자열 | 모든 아카이브 텍스트 |
| `PARAM.SFO`의 `TITLE` | 게임 메타데이터의 기본 제목 | RPCS3 사용자 지정 제목 |
| `ICON0.PNG` | 게임 목록 아이콘 | 인게임 타이틀 화면 |
| LINKDATA의 G1T | 인게임 메뉴·타이틀 이미지 | 게임 목록 메타데이터 |

## EBOOT 문자열 수정

현재 패치의 디스크 EBOOT는 길이를 유지한 디버그 SELF 형태이며, 개발 과정에서 RPCS3 실행을 확인했습니다. 이것을 실기 CFW PS3 호환성 보증으로 확대하지 않습니다.

고정 문자열은 번역 바이트와 NUL 종결이 기존 슬롯에 들어가는 경우에만 제자리 수정합니다. 더 긴 문구는 인접 데이터를 덮어쓰는 대신 참조 구조와 별도 풀의 사용 가능 여부를 먼저 분석해야 합니다.

키보드 분류·완료 버튼은 예외 사례입니다. 기존 슬롯 길이만으로 처리하지 않고, ELF 기준 `0xB2B7D0..0xB2B800`의 48바이트 영역에 여섯 라벨을 배치하고 `0xCF01A8`의 여섯 u32 포인터를 함께 갱신했습니다. 문자열 실사용 길이는 46바이트였습니다.

여기서 오프셋은 **해당 분석 대상 ELF 기준**입니다. SELF 파일 오프셋이나 런타임 가상 주소와 혼용하면 안 됩니다. 다른 빌드에 그대로 적용할 주소도 아닙니다. 문자열 검색 결과를 파일 전체에서 일괄 치환하는 방식은 사용하지 않습니다.

## 업데이트 1.06 실행 파일

게임 업데이트 1.06은 데이터 파일 없이 `USRDIR/EBOOT.BIN`(NPDRM SELF)과 `PARAM.SFO`·`ICON0.PNG`·`PS3LOGO.DAT`·`PARAM.HIP`만 담고 있습니다. 업데이트가 설치되면 게임은 디스크 EBOOT 대신 `dev_hdd0/game/BLJM61084/USRDIR/EBOOT.BIN`을 실행합니다. 그래서 디스크 EBOOT에 넣은 고정 문자열 번역은 업데이트 사용자에게 보이지 않습니다.

폭주 던전·요석·4회차 이후 전생 같은 업데이트 전용 문장은 LINKDATA가 아니라 이 업데이트 ELF의 UI 문자열 풀에만 있습니다. 디스크의 LINKDATA 전체와 디스크 EBOOT를 원시 검색해도 나오지 않습니다.

업데이트 패처는 다음을 업데이트 ELF에 적용한 뒤 디스크 EBOOT와 같은 디버그 SELF 형태(원래 SELF 헤더 유지, 키 리비전 `0x8000`, 평문 ELF)로 다시 감쌉니다. 파일은 원래 크기까지 0으로 채워 길이를 유지합니다.

- 디스크 EBOOT에 넣었던 문자열 번역 30곳. 같은 원문을 업데이트 ELF에서 다시 찾아 그 슬롯 안에 기록합니다.
- 키보드 분류·완료 버튼 라벨과 포인터 표. 업데이트 ELF에서는 표가 `0xD001A8`에 있고 라벨 영역도 디스크와 다른 위치입니다.
- 공통 고정 문구 19곳과 업데이트 전용 문장 32개.

새 글리프는 쓰지 않았습니다. 폰트에 없는 글자가 필요한 문구는 다른 말로 바꿨습니다(예: 랭킹 → 순위). 오프셋은 업데이트 1.06 ELF 기준이며 디스크 ELF와 섞어 쓰면 안 됩니다.

## PARAM.SFO 구조

SFO는 리틀 엔디언입니다. 헤더는 5개의 u32로 구성됩니다.

| 필드 | 내용 |
|---|---|
| magic | `0x46535000` (`00 50 53 46`) |
| version | 확인한 값 `0x00000101` |
| key_table_offset | 키 문자열 테이블 시작 |
| data_table_offset | 값 영역 시작 |
| entry_count | 엔트리 수 |

엔트리 구조는 `<HHIII`이며 16바이트입니다: key offset, format, data length, data capacity, data offset. 키와 값의 오프셋은 각각 자신의 테이블을 기준으로 계산합니다.

이번 패치는 `TITLE`만 `무쌍 오로치 2 얼티메이트`로 변경합니다.

- 형식 `0x0204`, UTF-8 문자열과 NUL 종결.
- 해당 TITLE 슬롯 용량 128바이트.
- 확인한 파일의 길이 필드 위치 184, 값 시작 위치 940.
- 전체 파일 크기 1,092바이트 유지.
- TITLE 길이 필드와 TITLE 슬롯 외의 바이트는 보존.
- `TITLE_ID=BLJM61084` 유지. 저장 데이터 연결이나 리전 식별을 바꾸지 않음.

이 위치들은 확인한 원본에만 해당합니다. 일반 SFO 도구를 만들 때에는 엔트리를 파싱해서 TITLE을 찾아야 합니다.

## ICON0.PNG와 고정 길이

목록 아이콘은 RGB **320×176** PNG이며, 원본 슬롯 길이는 **80,484바이트**입니다. 한국어 로고를 해당 크기로 리샘플링하고 PNG로 저장한 뒤 같은 길이를 유지하도록 구성했습니다.

단순히 PNG 끝에 쓰레기 바이트를 덧붙인 것이 아닙니다. `IEND` 앞에 `npAd`라는 ancillary chunk를 넣고 다음 PNG 청크 구조를 지킵니다.

```text
u32 BE payload_length | 4-byte chunk_type | payload | u32 BE CRC
CRC = CRC32(chunk_type + payload)
```

패딩 payload는 0바이트들로 구성되며, CRC를 계산합니다. 최종 길이가 원본과 같고, 패딩 전후 PNG 디코딩 픽셀이 동일한지 확인합니다. 슬롯보다 큰 결과물은 패딩으로 해결할 수 없으므로 먼저 이미지 인코딩 크기를 줄여야 합니다.

## ISO 반영

확인한 원본 ISO에서 SFO는 `0xF0800`, ICON0는 `0xF1000`에 있습니다. 배포 패처는 이 숫자를 임의 대상에 고정 적용하지 않고 ISO9660 디렉터리를 읽어 파일 extent를 찾습니다.

실제 설치 ISO에서 두 파일을 다시 읽어 제목·크기·해시를 독립 확인했습니다. 다만 최신 제목·아이콘의 RPCS3 화면 표시까지 재확인한 기록과는 구분해야 합니다. [검증 상태](validation.md)를 참고하세요.

RPCS3 목록에 다른 이름이 보일 때에는 실제 실행 중인 ISO/폴더와 사용자 지정 제목을 먼저 확인합니다. 패처는 에뮬레이터 설정을 바꾸지 않습니다.
