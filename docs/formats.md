# 파일 포맷

대상은 일본판 디스크(`BLJM61084`)의 `PS3_GAME/USRDIR` 아래 세 파일이다.

| 파일 | 크기 | 역할 |
|---|---|---|
| `EBOOT.BIN` | 14,167,896 | 실행 파일(SELF). 고정 UI 문자열 일부가 들어 있다 |
| `LINKDATA.IDX` | 1,198,592 | 아카이브 색인. 32바이트 레코드 × 37,456 |
| `LINKDATA.BIN` | 9,259,816,960 | 텍스트·이미지·폰트를 포함한 리소스 아카이브 |

`bgm`, `movie2d` 등 나머지 미디어는 건드리지 않는다.

## LINKDATA.IDX

레코드는 32바이트 빅엔디언 `>QQQQ`:

| 필드 | 의미 |
|---|---|
| `offset` | LINKDATA.BIN 안의 시작 위치 |
| `unpacked_size` | 압축 해제 후 크기 |
| `stored_size` | 실제 저장 크기 |
| `compressed` | 1이면 PS3 블록 압축 |

엔트리의 **슬롯 용량**은 다음 엔트리의 `offset`까지이며, 교체 데이터는 이 용량을 넘을 수 없다.
그래서 모든 교체는 슬롯 안에서 끝나고, `offset`은 바꾸지 않으며 `unpacked_size`/`stored_size`만 갱신한다.
결과적으로 세 파일의 크기가 원본과 같게 유지되고, 이것이 빠른 패처가 ISO 파일 시스템 메타데이터를 건드리지 않아도 되는 이유다.

## PS3 블록 압축

압축 엔트리는 zlib 스트림을 고정 블록으로 나눈 커스텀 컨테이너다. 해제·재압축 도구를 만들어
무수정 왕복이 바이트 단위로 같음을 확인한 뒤 사용했다. 재압축 결과는 대개 원본보다 작아
텍스트가 늘어나도 슬롯 안에 들어가지만, 넘치면 설치기가 거부한다.

## 폰트 아틀라스 (entry 42)

| 항목 | 값 |
|---|---|
| 컨테이너 | G1T, 플랫폼 PS3 |
| 텍스처 | 4096 × 2048, DXT5 |
| 저장 셀 | 32 × 16 (게임 표시 16 × 16) |
| 격자 | 128 × 128 |

셀 주소는 `x = (index % 128) * 32`, `y = (index // 128) * 16`. 같은 문자가 두 face로 들어 있어 둘 다 교체해야 한다.
한글은 Shift-JIS 2바이트 코드 영역의 셀을 재활용해 넣고, 텍스트는 그 코드로 인코딩한다.
DXT5의 알파 채널이 글리프 커버리지이므로 알파 블록만 바꾸면 이웃 글리프는 그대로다.

영문판(`NPUB31505`)은 1바이트 폰트만 직접 참조해 2바이트 문자가 빈칸으로 나오므로 일본판을 기준으로 삼았다.

## 이미지 텍스트

메인 메뉴·옵션·타이틀·전장 제목 등은 동적 폰트가 아니라 G1T 텍스처(BGRA8888 또는 DXT)에 그려진 이미지다.
텍스처 헤더와 크기는 그대로 두고 픽셀 영역만 다시 그려 같은 엔트리에 재압축해 넣는다.

## EBOOT.BIN

실행 파일 안에 CP932로 박힌 고정 UI 문자열(세이브 슬롯, 진군/철수, 진형 알림 등)이 있다.
원래 길이를 넘지 않는 범위에서 제자리 교체하고 남는 자리는 널로 채운다.
수정을 위해 SELF를 풀었다가 같은 길이의 디버그 SELF(키 리비전 `0x8000`)로 다시 감싸므로 파일 크기는 그대로다.
RPCS3는 폴더형 게임과 ISO 어느 경로에서든 이 형식을 그대로 실행한다. 실기(CFW)는 확인하지 않았다.

## ISO 안의 위치 (ISO9660)

| 파일 | 시작 오프셋 | extent |
|---|---|---|
| EBOOT.BIN | `0x780000` | 1 |
| LINKDATA.IDX | `0x18E1800` | 1 |
| LINKDATA.BIN | `0x1A06800` | 9 (4 GB 제한 때문에 1,073,739,776바이트씩 연속 분할) |

패처는 이 값을 하드코딩하지 않고 매번 ISO9660 디렉터리를 읽어 찾는다.
